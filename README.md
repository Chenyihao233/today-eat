# 今天吃啥 · 精简版

一个**纯前端、零后端**的家常菜小程序：抽菜决策 → 点菜 → 自动合并买菜清单。
双击 `index.html` 就能用，数据存在浏览器本地（localStorage），不需要账号、不需要服务器、不联网。

> 这是参考 [tidy-cookbook](https://github.com/RUIIIOVO/tidy-cookbook) 的思路做的精简 MVP（MIT）。
> 区别：去掉了多人实时同步、账号体系、AI 配图，只保留一个人能立刻用起来的核心流程。

## 快速开始

**电脑上**：双击 `index.html`。

**手机上**（推荐，体验最接近 App）：

```bash
cd today-eat
python -m http.server 8000
```

然后手机连同一个 Wi-Fi，浏览器打开 `http://<电脑局域网IP>:8000`。
iPhone Safari → 分享 → 「添加到主屏幕」；安卓 Chrome → 菜单 → 「添加到主屏幕」。
之后就是一个全屏、有图标、能离线用的「App」。

## 四个页面

| Tab | 干什么 |
|---|---|
| 抽菜 | 按荤/素/海鲜/汤羹/主食/减脂筛选，卡片左右拖动换一道，最近抽过的 6 道不会重复 |
| 菜谱 | 43 道家常菜，支持菜名 / 全拼 / 首字母 / 食材搜索（`xcr` → 小炒肉），点开看食材分级和做法 |
| 点菜 | 加减份数，锁单时选「今天/明天/后天」×「早/午/晚/宵夜」 |
| 清单 | 自动把多道菜的食材按**同名同单位**合并累加、按份数倍乘，勾选状态本地保存，可一键复制成文本发微信 |

## 一起点菜（多人实时同步）

页面右上角有个「一起点菜」按钮：

1. 点它 → **创建房间**，会得到一个 4 位房间码（比如 `K3F9`）
2. 点 **复制邀请链接** 发到微信，家人点开就自动进同一个房间（链接形如 `?room=k3f9`）
3. 之后两边加菜、加减份数、勾买菜清单、锁单，**对方屏幕上 1 秒内就变**

不加入房间时就是原来的单人模式，数据只存在本机。

### 它是怎么实现的

没有服务器、没有账号，用的是 [ntfy.sh](https://ntfy.sh) 的公开话题当**共享操作日志**：

- 每个动作（加一道菜 / 勾一项 / 锁单）打包成一条 JSON 操作发到该房间的话题
- 其他人用 `fetch` 长连接接收推送，按 `opId` 去重后在本地重放
- 新人进房间时先拉全部历史（`since=all`）重建完整状态
- 流断了会自动重连，连续失败两次则退回 6 秒轮询兜底
- 操作是**增量**的（`+1`/`-1` 而不是覆盖数量），两个人同时点不会互相盖掉

### 要知道的限制

- 话题是**公开**的：知道房间码的人都能读写。家庭内部够用，别往里放敏感信息（反正只有菜名）。
- ntfy 免费版**消息只保留 12 小时**，超过之后新进房间的人看不到更早的操作。
- 依赖 ntfy.sh 的可用性；国内偶尔会慢，但基本能连。

## 怎么加自己的菜

只改一个文件：`js/data.js`，照着已有格式复制一条：

```js
{
  id: 44,                     // 递增，用过不要改
  name: '辣椒炒蛋', py: 'la jiao chao dan',   // py 每个字一个音节，空格分开
  cat: '素菜',                 // 荤菜 / 素菜 / 海鲜 / 汤羹 / 主食 / 减脂
  e: '🌶️', desc: '一句话说吃起来什么样', spicy: 1,
  tags: ['快手', '下饭'],
  ing: [['主', '鸡蛋', '3个'], ['辅', '青椒', '2个'], ['调', '盐', '适量']],  // 主 / 辅 / 调
  steps: ['第一步……', '第二步……']
}
```

`py` 会自动生成全拼和首字母两种索引，不用另外写。
数量支持 `200g`、`4个`、`半勺`、`适量`——数字+单位的会合并累加，`适量` 这种只去重不累加。

## 菜品照片

每道菜两张图，按 `id` 命名，**加菜时不用改代码**，把图丢进去就行：

```
images/dishes/<id>.webp   800×800 大图，抽菜卡片和详情页用
images/thumbs/<id>.webp   240×240 缩略图，列表用（省流量）
```

没有图的菜会自动退回 emoji（不会出现破图），所以你可以一批一批慢慢补。

现有 43 张来自网络图搜（每张的来源链接记在 [images/credits.json](images/credits.json)），**只适合自己家里用**。
如果要公开发布，建议换成：自己拍的、AI 生成的、或者 CC0 图库的图。

批量处理可以用 `_tools/` 里那两个脚本（需要 Pillow）：`fetch_dish_images.py` 抓图、`make_thumbs.py` 生成缩略图。

## 目录

```
today-eat/
├─ index.html        入口（双击即可）
├─ css/style.css     纸墨极简样式，移动端优先
├─ images/
│  ├─ dishes/        菜品大图 <id>.webp
│  ├─ thumbs/        列表缩略图 <id>.webp
│  └─ credits.json   每张图的来源记录
└─ js/
   ├─ data.js        43 道菜的数据（唯一需要你改的文件）
   ├─ core.js        纯逻辑：拼音索引 / 搜索 / 抽菜去重 / 食材合并
   └─ app.js         视图渲染、手势、弹层、localStorage
```

## 下一步（想做成完整版时）

1. **多人实时同步**：把 `state.cart` 换成一个后端。最省事的是 Supabase（Postgres + Realtime + Auth，免费额度够家用），改 `core.js` 之外的一层同步即可。
2. **图片**：把 `e`（emoji）换成 `<img src="images/1.webp">`，再补一个 `img` 字段即可。
3. **上线**：整个目录丢到 Cloudflare Pages / Vercel / GitHub Pages 都行，纯静态零成本；国内访问建议绑自己的域名。
4. **小程序**：这套 DOM 代码不能直接搬，需要 Taro / uni-app 重写，并用微信云开发替代本地存储。

## 已知取舍

- 数据只在当前浏览器里，换设备/清缓存会丢（要跨设备就得上第 1 步的后端）。
- 没有账号、没有排行榜、没有下厨日历——都属于「确认家人真的会用」之后再加的东西。
